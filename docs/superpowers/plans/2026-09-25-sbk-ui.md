# SBK UI implementation plan

Goal: implement the approved host UI and validated renderer options without changing guest menus.
Architecture: keep RecompFrontend widgets/input and use an owned theme and allowlisted asset staging. Patch pinned renderer/frontend only for real settings. Run Model D with responsive host UI and owned child lifecycle.
Spec: docs/UI-DESIGN-SYSTEM.md and docs/GRAPHICS-CAPABILITIES.md.
Execution: continue implementation as explicitly authorized by the user; independent domains may execute in parallel under dispatching-parallel-agents.

Constraints: no ROM-derived assets; no guest timing changes; no high FPS UI; no unsupported controls; preserve .sbks/PFS; user-data persistence; no main merge/tag/release/force push.
Review focus: malformed numeric config, stale staged assets, unsupported VSync Off, child cancellation/reaping, narrow viewport focus visibility.
